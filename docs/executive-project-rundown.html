01
Purpose & scope

What this website is for

The site is the public face and the operating system of the Adeyinka Bakare Fellowship — a student-focused scholarship and mentorship community rooted in the Department of Information Technology at the University of Ilorin. It has two jobs: to tell the truth about the fellowship to prospective members, partners and beneficiaries, and to give the admin team a reliable place to publish, organise and measure that work.

Content is deliberately grounded in the ABF constitution and in real database records. Where a fact is not known, the interface says so rather than inventing a testimonial, rating or statistic. That decision runs through the whole build.

PUBLIC WEBSITE
Discover the mission, programmes, events, news and the many ways to take part. Every route is responsive, accessible and driven by published content.
  
ADMIN CONSOLE
Manage content, media, people, applications, email and security behind a permission model that reflects real responsibilities.
02
Design system

A brand that behaves consistently

ABF's visual identity is encoded as design tokens in globals.css, not scattered as one-off hex values. That makes the maroon, gold and cream palette behave the same way in a hero, a dashboard card and an email.

Maroon
Primary actions, links, dark editorial surfaces
  
Gold
Highlights, badges, ceremonial accents
  
Cream
Reading surfaces and calm page backgrounds
Typography & icons

Libre Baskerville carries headings and editorial moments; Plus Jakarta Sans handles body copy and interface text. The contrast gives the brand a serious, scholarly voice without sacrificing readability on a phone.

Lucide supplies a single, consistent icon language across navigation, cards, forms, admin tables and the weekly email. Icons are decorative by default (aria-hidden) so screen readers hear the label, not the shape.

White is reserved for maroon-500 and darker. Motion — reveal animations, count-up statistics, hover lifts — is present but restrained, and respects reduced-motion preferences.

04
Admin console

The control room behind the website

DAY-TO-DAY OPERATIONS
Dashboard with live counts, shared list and form components, resource CRUD for news, events, programmes, media, content blocks, volunteers, admins and social links, plus a command-palette search and breadcrumb-aware header.
  
COMMUNICATION & TRUST
Email studio and logs, notification centre, event application responses, volunteer status updates, an audit trail, MFA and passkey settings, and an active-sessions view where devices can be reviewed and revoked.

The admin area uses the same design tokens as the public site, so a new administrator does not have to learn two visual languages. Navigation, destructive actions and palette choices are gated by role rather than hidden by convention.

05
Latest editorial work

Newsroom, media and sharing

The public news listing was rebuilt as an editorial page: a featured split-card story, a quieter “More from ABF” grid, stronger typographic hierarchy and responsive behaviour that still reads well with a single published story.

On article pages, the complete image is now shown in a full-media figure rather than being cropped into an invisible header. Event detail pages received the same treatment, so a poster or photograph is presented as content, not decoration.

Calls to action authored inside articles now keep white text on maroon, and older stored HTML is covered by compatibility selectors. The share control was generalised into one component used by both news and events: native share where available, copy-to-clipboard and a toast everywhere else.

A related bug in news creation was fixed at the repository layer: a slug-availability lookup used a single-row query that raised PGRST116 when the slug was free, and the insert now returns the created row through the admin client so RLS cannot hide it.

06
Email & automation

The weekly digest

A weekly letter is generated from the previous completed Monday–Sunday week. It gathers published news, events and upcoming dates, new members and subscribers, volunteer and application activity, and a set of operational metrics. Two HTML emails are produced: a long, member-facing letter with reflection, encouragement and practical student advice, and a separate confidential admin report covering security, database health, email delivery and recommended actions.

MEMBER LETTER
Table-based responsive layout, quick-navigation pills, stat cards, story cards with images, collapsible sections for longer reading, animation with reduced-motion fallback, and personalised unsubscribe links.
  
ADMIN REPORT
Audit activity, MFA and passkey coverage, active sessions, mail failures, content and media volume, volunteer backlog and an explicit recommendation list for the week ahead.

Recipients are deduplicated by lowercase email across members, subscribers and admins. Admins receive the member letter once, plus the confidential report. Idempotency is enforced by a weekly_digest_runs row and by email-log metadata keyed to the week, so a repeated cron call does not resend the issue.

07
Security model

Least privilege, by default

Supabase Row Level Security is the boundary for public and authenticated traffic; service-role access is confined to trusted server code such as repositories and cron jobs. A permission matrix maps roles to capabilities, and the same rules are enforced in route handlers, navigation and UI actions — a hidden button is never the only control.

Privileged accounts support TOTP, passkeys and email OTP, with MFA requirements recorded per admin. Sessions are visible and revocable, and admin actions are written to an audit log that the weekly report summarises. The cron endpoint accepts a shared secret by query parameter or header and fails closed in production when no secret is configured.

Institutional memory

What the team learned

CSS-first themingTailwind v4 keeps the palette in CSS variables. Tokens survive refactors; scattered hex values do not. Cascade layers matter when authored article HTML needs to override prose defaults.
Server/client boundaryNext.js App Router rewards keeping data access on the server and isolating only interactive islands — share buttons, forms and dialogs — in client components.
Two layers of trustRLS plus a permission matrix is stronger than either alone. Service-role code must stay server-side and be reviewed as a privileged boundary, especially where a single-row query can throw on zero rows.
MFA is a workflowPasskeys and TOTP are not just toggles: enrolment, verification, recovery, session revocation and clear user-facing status all have to work together.
Email is a different webTable layouts, inline-friendly styles, modest animation and progressive enhancement (details/summary) travel further across clients than modern page CSS does.
Automation needs brakesIdempotency by week, recipient deduplication, a dry-run switch and a well-defined auth contract turn a cron job from a risk into a routine operation.
